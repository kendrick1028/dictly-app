# Dictly 기능 기회 (워크플로 공백 기반)

_방식: 학습 워크플로(녹음→전사→복습→암기→자가시험→시험대비→기억유지)의 실제 공백을 코드 근거로 발굴. 각 기능은 (a)구체적 공백 (b)제품 정체성 부합 (c)저클러터(점진적 공개) (d)복잡도 대비 값어치 를 모두 충족. 각 아이디어는 "불필요/과잉/클러터" 반증을 통과한 것만 수록. 참고 제품은 공백 파악용일 뿐 복제 대상 아님._

## 총평 — 가장 큰 공백
Dictly는 **생성(스튜디오 8종)은 풍부하지만 기억유지 루프가 열려 있다.** 두 공백이 맞물린다:
1. **기억률을 "측정"만 하고 "행동"으로 잇지 못한다.** `main/home.ts`가 과목별 에빙하우스 곡선을 계산하지만, Home의 기억률 섹션(`Home.tsx:397`)은 곡선을 그리고 "…천천히 감소해요"로 끝나는 수동 차트다. "오늘 뭘 복습해야 하는지"를 말해주는 곳이 없다.
2. **암기·자가시험 드릴(플래시카드·퀴즈)이 기억상실 상태다.** 가장 자주 반복하는 드릴인데 결과를 저장하지 않아 기억률 모델에 신호를 0으로 준다(파인만만 상태를 저장·적응). 이 불일치가 핵심.

즉 **녹음→전사→복습→암기까지는 탄탄한데 자가시험→기억유지 구간에서 신호가 끊긴다.**

## 기회 (고레버리지·저클러터 순)

### 1. "오늘 복습" — 기억률 곡선을 한 번의 행동으로 · confidence 상
- **공백/근거**: `main/home.ts`가 과목별 `retention = 100·exp(-daysSince/stabilityDays)`를 산출하나 소비처는 `Home.tsx:397 RetentionSection`의 수동 SVG 곡선뿐. 유일한 재노출 "진행 중인 파인만 복습"은 *미완료 세션*이지 "세법이 40%로 떨어졌으니 오늘 복습"이 아님. 알림 인프라(`main/scheduler.ts:38`)는 이미 있으나 수업 알림에만 사용.
- **누가 이득**: 여러 과목을 굴리는 시험 준비생 — "오늘 어느 과목을 볼지" 판단 부담 제거.
- **왜 지금**: 입력(과목별 retention%·daysSince·파인만 라운드 재생성)이 전부 존재. 새 모델링이 아니라 배선.
- **범위/난이도**: 소~중. Home 기억률 섹션을 "가장 낮은/오래 안 본 과목 1~2개 → 탭 한 번에 해당 과목 최신 파인만을 복습 모드로 열기(없으면 생성)"로. 선택적으로 임계치 하회 시 조용한 알림.
- **저클러터 방식**: 새 화면 없음. 기존 수동 곡선 섹션을 *복습할 게 있을 때만* 뜨는 액션 행으로 교체(점진적 공개).
- **리스크/안티골**: 밀린 개수·스트릭으로 불안 유발 금지. 제안 1~2개 상한, dismiss 가능.

### 2. 플래시카드·퀴즈 "결과 기억" — 가볍게 기록해 기억률에 연료 공급 · confidence 상(필요)/중(UI)
- **공백/근거**: `studio/views/FlashcardsView.tsx`는 순수 뒤집기(아는/모르는 상태·저장 없음). `QuizView.tsx:18-21`은 점수를 `useState`에 담고 item 전환 시 리셋 → 오답 로그·"틀린 것만 다시" 없음. `db.ts:143 studio_items`엔 `content_json`만, 카드별 상태 컬럼 없음. `home.ts`의 retention은 파인만(`fCount/fScoreSum`)만 반영 → 매일 카드를 갈아도 기억률엔 0.
- **누가 이득**: 암기 비중 큰 학습자(회계 계정·세법 조문) — 파인만보다 훨씬 자주 도는 드릴.
- **왜 지금**: 기회 1의 *연료*. 값싼 고빈도 신호가 없으면 기억률 모델이 파인만 전용으로 대부분 빈다.
- **범위/난이도**: 중. 카드/문항별 최소 결과(마지막 정오답+시각)를 studio 콘텐츠에 저장. 플래시카드에 **2상태 "알아요/모르겠어요"**(4버튼 SM-2 아님), 퀴즈 "다시 풀기" 기본값을 **"틀린 것만"**으로. 세션 정답률을 파인만과 같은 방식으로 `stabilityDays`에 합류.
- **저클러터 방식**: 카드 아래 버튼 2개(또는 스와이프) + 기존 "다시 풀기" 기본값 변경. 새 화면·덱 매니저·간격 설정 노출 없음.
- **리스크/안티골**: Anki화 절대 금지(Again/Hard/Good/Easy·ease·간격 편집). 이진 판정 + 비가시 스케줄 유지.

### 3. 과목 전체 복습 모아보기 — 강의 횡단 북마크·오답 집계 · confidence 중
- **공백/근거**: `tabs/BookmarksTab.tsx:25-29`는 `memo.bookmarks`/`memo.segments`만 읽어 북마크가 *한 강의 안*에 갇힘. 시험대비엔 "이 과목의 표시한 모든 부분/모든 오답"을 10~15강 걸쳐 봐야 하나 폴더 레벨 집계가 없다. 폴더 스튜디오는 *새 생성*은 되나 이미 표시·틀린 것을 모아주진 못함.
- **왜 지금**: 폴더 스코프가 이미 존재(`useStore.ts` `studioScope:'folder'`·`folderSrcMemoIds`). 기존 북마크(+기회2 오답) 위의 읽기전용 집계라 대부분 쿼리.
- **범위/난이도**: 중. 폴더 뷰에 "과목 복습" 렌즈 — 모든 북마크 청크를 강의별 그룹핑(각 소스로 점프), 기회2 이후엔 놓친 퀴즈·카드까지.
- **저클러터 방식**: 새 전역 탭 아님. 폴더 뷰/스튜디오 안, `BookmarksTab`의 카드+점프 패턴 재사용.
- **리스크/안티골**: 새 노트 타입 만들지 말 것 — 기존 표시 위의 렌즈로만.

### 4. (확장·낮음) 시험 레이더에 "내 약점" 오버레이 · confidence 중/하
- **공백/근거**: `studio/views/ExamRadarView.tsx`의 점은 전사문 기반 중요도×난이도로만 크기·색이 정해짐 — *내 숙련도*는 없음. 기회2/파인만 결과가 개념별로 쌓이면 "중요·어려운·내가 약한" 점을 진하게 칠할 수 있음.
- **왜 지금**: 기회2 선행 필요. 레이더는 이미 값에 따라 accent 농도를 바꿈 → 숙련도 틴팅은 증분.
- **범위/난이도**: 중. 카드/문항→레이더 노드 매핑이 애매(가장 어려운 부분). 선택적·낮은 우선순위.
- **리스크/안티골**: 매핑 오류로 오해 유발 가능.

## 안티피처 (만들지 말 것)
- **완전한 Anki식 SRS**(Again/Hard/Good/Easy·ease factor·간격 수동편집·덱 관리) — "쉽게+설명 없이" 철학 정면 위배. 기회2의 2상태 판정이 적정 용량이고, 풀-SRS가 바로 그 함정.
- **수동 덱/카드 저작**(직접 카드 만들기·태그·중첩 덱·템플릿) — 소스에서 생성하는 차분한 모델을 카드 관리 노동으로 바꿈.
- **게임화**(스트릭·XP·배지·리더보드) — 표면적 장치. 기억률 곡선이 이미 정직한 "스트릭". 시험생은 신호를 원하지 컨페티가 아님.
- **소스 무관 범용 챗봇/AI 튜터 페르소나** — Spotlight·스튜디오 채팅은 이미 소스 기반. 자유 대화는 환각·탈선을 부르고 "근거 인용" 정체성 훼손.
- **협업/공유/스터디그룹** — 로컬 우선 STT 프라이버시 정체성과 충돌, 스코프 폭발.
- **클라우드 동기화/모바일·웹 컴패니언** — 큰 인프라, 로컬 우선과 배치, 워크플로 공백도 아님.
- **NotebookLM식 오디오 오버뷰·영상 내보내기** — 소비 노벨티(기억유지 공백 아님). 무겁고 산만.
- **무거운 독립 "모의고사" 엔진**(타이머·과목 전체 시험 시스템 별도 구축) — 파워는 늘지만 클러터 위험 큼. 필요한 값어치는 기회2 "틀린 것만" + 기회3 집계로 대부분 커버; 정 필요하면 퀴즈 안 가벼운 타이머 옵션으로 족함.
